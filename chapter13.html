Chapter 13: Catching Bugs (Error Handling)

1. What are Exceptions?

Sometimes you write code that makes sense to you, but the computer gets confused (like dividing by zero). When this happens, Python throws an Exception (an error) and crashes! We call these errors "Bugs".

Example A: A ZeroDivisionError

print(10 / 0) # CRASH!

Example B: A TypeError

print("Apples" + 5) # CRASH!
Assignment 1: Cause a Crash!

2. The Try Block

To prevent our program from crashing, we can put dangerous code inside a try block. This tells Python: "Try to do this, but if you fail, don't panic!"

Example A: Try block syntax

try:
    print(10 / 0)

Example B: Try needs except

# Try must always have an except block after it!
Assignment 2: Try to Divide

3. The Except Block

If the code inside the try block crashes, Python instantly jumps to the except block instead of crashing the whole program. This is how we catch bugs!

Example A: Catching an error

try:
    print(10 / 0)
except:
    print("Oops! You can't divide by zero!")

Example B: The program continues!

# The program keeps running after the except block!
Assignment 3: Catch the Bug!

4. Catching Specific Errors

Some bugs are different than others. You can tell Python exactly which bug you are looking for so you can give the right error message.

Example A: Catching a ValueError

except ValueError: print("Not a number!")

Example B: Catching a ZeroDivisionError

except ZeroDivisionError: print("Can't divide by 0!")
Assignment 4: Specific Bug Catcher

5. The Finally Block

Sometimes you want a piece of code to run no matter what happens, whether there was a crash or not. We use the finally block for this.

Example A: Finally block

finally:
    print("I always run!")

Example B: Used for cleanup

# Usually used to close files or clean up memory.
